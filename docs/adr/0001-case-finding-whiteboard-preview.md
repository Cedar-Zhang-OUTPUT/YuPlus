# ADR-0001：找案例功能采用画板图片预览，由本地程序自动刷新

- 状态：已接受，已实现并验证（v0.3.20）
- 决策日期：2026-10-23
- 适用范围：后续新增的“找案例”功能

## 背景

找案例时，用户需要在 Yu+ 前端直接查看飞书内容中的画板，减少在应用与飞书之间切换。当前 Yu+ 以本地服务、飞书 CLI 和只读前端为基础，案例库仅登记共享文件夹或网站，查找和读取在飞书端按需进行。

本决策针对新功能的展示能力，与已有项目来源、draft、review 对象没有直接关联。它不是 Review 导出流程或现有对象模型的扩展。

## 决策

### 1. 显示画板的图片预览

在找案例界面显示由飞书画板导出的图片，支持放大、缩放，并保留原文档或画板的可用跳转入口。预览是获取时刻的快照，不是可编辑的飞书画板，也不承诺实时协作。

新功能保留获取预览所需的文档/画板定位信息及最近成功获取时间。具体字段与界面布局在该功能的设计中确定。

### 2. 刷新由本地程序完成

本地服务通过飞书 CLI 的画板导出能力获取图片，前端通过本地服务显示预览。正常刷新不触发 Agent、不消耗模型推理，也不依赖 Codex 对话或 Agent 定时任务。飞书凭据由现有本地认证机制管理，不传给前端。

- 打开画板预览时，先显示已有可用快照，再在后台获取最新预览；首次没有快照时显示加载状态。
- 用户持续查看时，程序定期刷新当前可见画板；离开、隐藏页面或关闭预览后停止该预览的定期刷新。
- 提供手动刷新入口，调用同一获取流程；避免并发重复请求以及旧请求覆盖较新的结果。
- 仅在获取并验证新图片成功后替换旧图，不在刷新期间清空已有预览。
- 普通网络失败保留旧图，显示最近成功获取时间与失败提示，并采用退避重试。认证失效或权限不足时暂停自动重试并提示处理；必要时由用户或 Agent 协助恢复认证，恢复后可继续刷新。

实现参数：可见时每 60 秒刷新、前端请求超时 30 秒、服务导出超时 24 秒；失败指数退避至最多 5 分钟，同一数据目录导出串行化并合并重叠成功请求。本决策不采用群聊监控的默认一小时间隔，也不假定存在可靠的画板 revision 检查接口；是否可先检查变化以减少图片下载，需按实际接口能力核实。

### 3. 不建立项目对象关联

预览定位和刷新状态属于找案例功能自身。显示或刷新画板不创建项目 source、draft、review，不增加这些对象的依赖关系，不触发业务内容更新或决策记录。程序自动更新的是预览图片，不是对案例内容的理解。

### 4. 保持案例内容在飞书

不抓取整个共享文件夹，不持久化案例正文、附件集合、目录清单或搜索索引。图片只作为按需展示所需的可清理临时预览缓存，放在业务数据与备份之外；不进入项目文件池，也不成为独立维护的案例材料库。

仅对用户正在查看的画板获取和刷新。缓存最多 32 张 / 128 MiB，7 天过期，在成功刷新时清理；缓存丢失后可重新获取，飞书原内容仍是唯一权威来源。该展示缓存不改变现有案例库的“远端查找、本地仅登记”原则。

## 取舍与边界

- 采用图片预览可复用本地服务和 CLI，不必为此接入完整飞书文档组件及其网页鉴权流程。
- 图片不具备原画板的编辑、节点交互或实时同步能力；需要这些能力时打开飞书原内容。
- 完整云文档嵌入、可交互画板、案例与项目对象的业务关联均不在本 ADR 范围。
- 已用独立飞书验收文档完成真实图片写入、同轮追加、本地定时预览及新标签页跳转验证；权限/失败分支使用可注入测试验证，没有更改真实账号权限。

## 实现验收要点

1. 真实可访问画板能在找案例页面显示、放大并跳转原内容。
2. 无 Agent 参与时，打开及持续查看可自动获取更新；离开后不再周期请求。
3. 网络失败、认证失效和权限不足均有明确反馈，旧快照不被误标为最新；重叠请求不会回退图片版本。
4. 刷新不会创建或修改项目 source、draft、review、业务决策，也不会遍历案例库或将预览纳入业务备份。

## 依据

- 用户确认：画板用于新的找案例功能，与前面对象不造成直接联系；将画板预览、程序自动刷新的决定记录为 ADR。

## 实施进展（2026-10-23）

已接入 Schema 7 研究元数据及幂等回执、`research create/update/list/show/preview`、只读预览/图片 API，以及跨进程去重的临时缓存。Agent 使用飞书 CLI 创建和编辑画板；服务只负责导出预览。独立轮次绑定独立画板，同轮修改保持版本，普通刷新不更新研究业务时间。

真实验证：v1 三张真实案例截图写入并显示；另建 v2 画板；v1 追加说明后，页面未点击刷新便通过 60 秒计时器显示新图片散列，仍是 v1。原 15 节点保持不变。详细证据及边界见 [链路验证](../testing/case-research-integration.md)，接口见 [前端接入契约](../../frontend/case-finding-contract.md)。随 v0.3.20 发布。
