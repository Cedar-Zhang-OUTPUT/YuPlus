## 3. 当前真实能力边界（集成前必须明确）

1. **界面设计完成不等于正式产品完成。** app.js 直接 import 模拟 DATA；所有项目、来源、版本、反向引用和 diff 均是前端视图模型。尚未读取真实 Yu+ 数据目录或数据库。
2. 预览 server 不是 `yu serve`，没有真实项目 API；除受控 Finder 定位端点外拒绝写入方法。没有真实飞书读取、导出或媒体管线。
3. 飞书/网页“原文”链接在 demo 中被改成 `source.html?id=...`，虚构远端地址仅保留为示例元数据。正式集成必须恢复已保存的真实规范地址，不能把 demo URL 当生产链接。
4. 图片、PDF、视频等业务素材大多只有元数据和占位，没有真实原件。文本快照可查看；不得声称已有完整媒体预览能力。
5. 不伪造远端已检查、审核已通过、导出已完成等状态。`review_checks`、`exports` 的展示容器不代表现有 CLI 已有写入接口。
6. `review-prompts.js` 当前复制完整可携带的阅读快照（并非 CLI 写入 JSON）：所有 Review 实例、共用 Q&A、引用旧版/当前 draft、来源快照、依据状态。**demo 模式下“更新 Prompt”要求改模拟文件**；正式接入时必须切换为真实项目读取 → prepare → publish，不能沿用这个 demo 分支。
7. macOS Finder bridge 当前仅定位由已有模拟文本生成的缓存文件，不是飞书原件。非 macOS 或缺失真实文件时不显示入口。

## 4. 已确认的页面及交互（应保留，也应写进新 skill）

### 导航与项目

- 路由：项目列表 `/#/`；对象说明 `/#/types`；项目内 `/#/p/{project_id}/draft/{object_id}`、`review/{object_id}`、`sources`、`history`。对象路径可省略以进入对应场景。
- 左侧导航可展开/收起；项目内“信息收集”“整理与Review”，底部“原始材料”“变更与决定记录”。页脚有刷新时间和刷新按钮。
- 浏览路由不会更改 Agent 的项目身份或项目工作场景。复制引用携带准确的项目、对象/条目/段落及版本身份。
- 项目列表支持查找项目及空状态；新建项目引导是复制给 Agent 的指令，不是页面表单写业务数据库。

### 信息收集 / draft

- 23 类对象以分组目录+连续阅读区展示；目录可切换全部类型/已有内容，点击跳到对象，滚动更新选中项。
- 默认目录收起。hover 只打开悬浮目录，不改变其他组件比例；选择目标后自动收起；移出会关闭。只有点击展开才常驻并改变布局，常驻目录点击目标不会自动收起。
- 响应式布局下展开/收起向下展开，不应使“信息收集”主标题弹跳；保持阅读位置。不要回退到 hover 触发布局重排。
- 对象卡片显示版本、更新时间，版本切换可读历史并回到当前。不要恢复已删除的版本变更解释小字。
- 子卡片来源类型不常驻底部。hover 整张卡片，左侧彩色圆角边缘自然向外扩宽，竖排显示“原文陈述/用户补充/建议/采用决定”等；与原颜色条连为一体。
- 该效果由绝对定位装饰层实现，不改正文真实边框/宽度，避免 1px 抖动。甘特图详情预留左边空间，防止裁切扩展部分。
- 正文超过三行折叠，点击正文展开，再点折叠，支持键盘；短正文不伪装成可交互。窗口宽度变化重新测量。
- 来源行统一前缀“依据”；无来源时不显示“尚未记录来源依据”。原文标题打开原文，“查看引用”查看已保存快照，两者不同。
- 金额字段及自然语言金额亮红色。结构化金额按最小货币单位格式化；正文由前端规则自动识别，无需 Agent 在正文插 HTML。规则并非完美语义理解，正式接入不要修改原文来染色。
- Q&A 子卡片同时显示问题和回答；无回答显示待答复，不适用保留说明；不单列“答复依据：...”小字，证据走来源行。
- 不显示无意义“值”标签、“原话条目”内部 ID、“时间类型”等内部字段，但不能为此删除后台语义或证据。
- 时间轴同时支持按天和精确到分钟，时间节点/区间并存。甘特图标签不显示来源类型，不显示误导性的“点击查看详情”说明；节点可展开详细卡片。
- 交付时间线按轮次读内容，日期引用时间节点；参考日期不能伪装成已确认截止时间。

### 整理与 Review

- 五类成果：R01 主策 Debrief、R02 推进要素、R03 创意审查结果、R04 内外部创作者 Brief、R05 客户 Q&A。R04 支持多创作者/多轮次实例；R05 是同一 D15 的视图，不能另建重复对象。
- 主标题下通用解释性小字已删除；Q&A 的同源说明仍在标题下。
- 正文段落标题 20px，大于 16px 正文；移除标题右侧重复的 draft 跳转 chip。
- 每段底部右侧为“完整追溯路径”“复制引用”；前者可查看段落 → 所引用 draft 版本/条目 → 原始来源并跳转。
- 已变化依据提示橙色；仅实际引用条目发生变化时标记受影响段落，同一对象其他条目变化不能导致全部标脏。
- 变化 banner 有“查看受影响段落”和“复制更新 Prompt”。复制不等于已更新，不修改数据库或同步状态。
- 有差异的段落左下角显示黄色“查看差异”，与右侧两按钮同一底部操作区。
- 差异检查器有“当前成果采用的依据”“最新版本的依据”两张卡片，旧变更红色 −，新变更绿色 +，展示字段、信息性质和各版来源；未变化条目可展开。
- 原引用条目删除、新增多个替代条目时，不按同名猜一对一映射；按同一对象新旧版本列出移除与新增。缺失版本是无法比较，不得判定成新增/删除/已同步。多条依据变化支持选择查看。
- 主标题右侧显眼“复制飞书导出 Prompt”：面向整个项目所有当前 Review 内容和来源，含所有 Brief 实例与共用 Q&A，不限当前选中卡片。
- 导出是用户把 Prompt 发给 Agent 后，由 Agent 调飞书 CLI 新建文档、写入、回读核验并返真实链接；页面按钮本身只复制。不能在复制成功后显示“导出完成”。

### 来源、版本与系统交互

- 来源检查器：身份/规范 URL、本地已存快照及版本、正文、附件、反向引用；可切换历史快照。未检查远端不能称为最新。
- 反向引用必须基于持久化的真实证据；版本比对基于实际引用版本，不把当前快照替换进历史引用。
- Finder 文本附件入口仅可对登记的资产 ID 请求服务端解析文件。当前有同源/Host/JSON 校验、realpath 限制，用 `open -R` 定位；不得开放任意路径或 shell 命令接口。

## 6. 新增独立可视化使用 skill 的要求

建议以 `skills/yuplus-visualization/` 组织（最终名由接收方遵循仓库规范决定），主文件精简、具体页面说明放 references，中文说明同步。用 skill-creator 等适用规范校验；主 Yu+ skill 明确何时转到该 skill，而非假设自动加载。

必须基于最终集成后的**真实行为**编写，而非照抄设计目标。至少覆盖：

- 触发场景：用户问页面是什么、按钮怎么用、目录 hover 与常驻区别、怎么看来源/历史/变化、如何更新/导出、页面不刷新/服务不可达等。
- 环境与页面打开：检测实际运行地址/项目 ID，启动或复用服务，在 Codex 浏览器打开正确路由；不要假设永远是 7801，不关闭用户已有标签。
- 页面地图、组件名称、常见问题的直接回答、键盘/触摸与响应式可用行为；用截图及稳定语义标识辅助，不依赖固定坐标。
- 区分页面查看动作和 Agent 业务写入：复制引用/Prompt、打开原文、查看快照、Finder 定位分别做什么；复制不是更新或导出成功。
- 对“帮我改这里”的处理：先解析引用身份和版本，再调用业务 skill/CLI；纯 UI 操作不改业务数据；浏览不切换持久化工作场景。
- 依据变化的解释、新旧版本 diff、缺失/删除/未知的语义，以及如何由 Agent 检查并更新成果。
- 接收完整项目飞书导出 Prompt 时转到相关飞书 skill，读取真实内容、保留来源并核验结果。
- 故障分流：服务没启动、端口变化、历史版本、真实数据为空、缺失资产、剪贴板失败、飞书权限/登录、Finder 不支持；不把未知状态说成已完成。
- 按需读取已读说明，数据过期则刷新数据，避免每次问题都全量读取项目/所有 skill。
- 标注版本/代码入口，测试文档操作与实际 UI 一致，后续行为变化同步更新说明。
