# Yu+ 设计语言规范 v1.0

配套文件：`tokens.css`（唯一色值来源）· `specimen.html`（视觉样本）· `../screenshots/`（界面示例图）。

正式实现请**直接引用 `tokens.css`**，不要在业务组件里硬编码色值。
需要新增颜色时，先加语义变量，再在组件里引用它。

---

## 1. 设计原则

**结构取自 Apple，色彩承担信息含义。**
分层材质、连续圆角、分段控件、按需展开的检查器——这些是「怎么排」；
三套语义色——阅读主题、信息性质、来源类型——这些是「什么意思」。
颜色不是装饰，可以被读懂。

**四条不可让步的约束**（来自产品 Spec，属于设计的一部分）：

1. **不可把推断显示成客户原话。** 六种信息性质必须始终可辨：原文陈述、用户补充、
   转述、假设、建议、采用决定。同一对象里它们可以并存，不得合并、不得覆盖。
2. **状态色不表达 Agent 的工作进度。** 界面不得出现「已登记 / 读取中 / 部分读取 / 已处理」，
   也不得展示推定的审核状态。状态色只表达**已保存记录之间可验证的差异**。
3. **没有写操作入口。** 新建、上传、编辑、删除、保存意见、确认成果都不在页面里。
   需要写的时候，页面给出「在 Codex 中做」的说明与可复制的引用。
4. **未知不等于零。** 未记录就是「尚未记录」，不补零、不推定「不适用」、不显示为故障。

## 2. 色彩系统

### 2.1 阅读主题色 — draft 对象按主题分组

分组只改变展示，不新增业务对象。每个分组一个色相，用于目录小标题的色点、
对象编号底色、条目卡左侧 3px 边。

| 主题 | Token | 值 | 对象 |
| --- | --- | --- | --- |
| 背景与需求 | `--theme-background` | `#007AFF` | D01 D02 D03 D11 D13 D14 |
| 研究与资料 | `--theme-research` | `#30B0C7` | D04 D05 D06 D12 |
| 计划与协作 | `--theme-plan` | `#FF9500` | D09 D19 D20 D18 D07 D08 D16 |
| 判断与决定 | `--theme-judgment` | `#AF52DE` | D17 D22 D10 D21 D23 D15 |

### 2.2 信息性质色 — 核心约束的可视化

| 性质 | `epistemic_kind` | Token | 值 | 含义 |
| --- | --- | --- | --- | --- |
| 原文陈述 | `source_statement` | `--epistemic-source-statement` | `#007AFF` | 直接来自材料，可回到原文定位 |
| 用户补充 | `user_supplement` | `--epistemic-user-supplement` | `#34C759` | 主策补充，不是客户原文 |
| 转述 | `reported` | `--epistemic-reported` | `#30B0C7` | 经他人转述，可能有偏差 |
| 假设 | `hypothesis` | `--epistemic-hypothesis` | `#FF9500` | 尚未确认，不作事实依据 |
| 建议 | `suggestion` | `--epistemic-suggestion` | `#AF52DE` | Agent 或用户的建议，不是正式决定 |
| 采用决定 | `adopted_decision` | `--epistemic-adopted-decision` | `#5856D6` | 已采用口径，附决定依据 |

假设类内容除色标外还要有一句显式说明（「此条是假设/未核实信息，不是事实依据」），
不能只靠颜色。

### 2.3 来源类型色

| 类型 | `provider` | Token | 值 | 进入方式 |
| --- | --- | --- | --- | --- |
| 飞书 | `feishu` | `--provider-feishu` | `#007AFF` | 标题链接，新标签打开原文 |
| 本地文件 | `local` | `--provider-local` | `#30B0C7` | 文件预览 |
| 用户口述 | `oral` | `--provider-oral` | `#AF52DE` | 原话快照 |
| 网页 | `web` | `--provider-web` | `#8E8E93` | 地址提示 |

### 2.4 成果类型色

`--review-persistable`（`#5856D6`）用于 R01–R04；`--review-derived`（`#30B0C7`）
用于 R05，因为它读取 D15、不单独持久化。R05 在界面上要明示「这是同一份问题表，
不是另建的问题记录」。

### 2.5 状态色

| 状态 | Token | 值 | 用于 |
| --- | --- | --- | --- |
| 与当前一致 | `--state-ok` | `#34C759` | 当前版本、远端未变化、已答复 |
| 需要注意 | `--state-attention` | `#FF9500` | 依据已变化、远端有更新、待答复 |
| 中性/未知 | `--state-muted` | `#8E8E93` | 尚未记录、尚未检查、不适用 |
| 异常 | `--state-danger` | `#FF3B30` | 原件不可用、读取失败 |

### 2.6 中性层次

| Token | 值 | 用途 |
| --- | --- | --- |
| `--label` | `#1D1D1F` | 主文本 |
| `--label-2` | `#48484A` | 次要文本、字段值 |
| `--label-3` | `#8E8E93` | 三级：时间、计数、单位、对象编号 |
| `--label-4` | `#C7C7CC` | 分隔、禁用 |
| `--bg-page` | `#FBFBFD` | 页面底 |
| `--bg-elevated` | `#FFFFFF` | 卡片、检查器 |
| `--bg-grouped` | `#F2F2F7` | 分组底、代码块、快照正文 |
| `--bg-fill` | `rgba(120,120,128,.10)` | 分段控件底、次级按钮 |
| `--bg-sidebar` | `rgba(247,247,249,.72)` | 侧栏（叠加 blur） |
| `--separator` | `rgba(60,60,67,.12)` | 发丝分隔线 |

**标签的底色与文字色由基色派生**，不要为每个色相手写两套颜色：

```css
background: color-mix(in srgb, var(--h) 13%, transparent);
color:      color-mix(in srgb, var(--h) 82%, #000 8%);
```

组件里只设置 `--h`（语义色），标签样式自动派生。这样新增语义色时无需新增样式。

## 3. 字体

| 角色 | 规格 |
| --- | --- |
| 字体栈 | `-apple-system, BlinkMacSystemFont, "SF Pro SC", "PingFang SC", …` |
| 等宽 | `ui-monospace, "SF Mono", SFMono-Regular, Menlo` |
| 页标题 | `clamp(28px, 3vw, 38px)` / weight 700 / tracking `-0.032em` / line-height 1.12 |
| 卡片标题 | 19px / 700 / tracking `-0.021em` |
| 列表主行 | 15px / 620 |
| review 正文 | 16px / line-height 1.78 |
| 界面正文 | 15px / line-height 1.6 |
| 次要说明 | 13px |
| 时间/计数/单位 | 11.5px / `--label-3` |
| Eyebrow | 11.5px / weight 640 / uppercase / tracking `.07em` |

**等宽的使用边界**：对象 ID、条目 ID、版本号、来源 ID、路径、金额、
命令、时间戳一律等宽。**中文正文、标题、说明一律不用等宽。**

数字统一 `font-variant-numeric: tabular-nums`，保证列对齐。

## 4. 形状与深度

**圆角**：`--r-xs` 6px（行内代码）· `--r-sm` 10px（输入框、紧凑按钮）·
`--r` 14px（条目卡）· `--r-lg` 20px（卡片、成组列表）· `--r-xl` 26px（模态、空态）。

**阴影**：靠发丝线而不是重阴影建立层次。
`--shadow-1` 用于选中态与统计块，`--shadow-2` 用于卡片，
`--shadow-3` 只用于模态与浮层。卡片默认边框透明、靠圆角与阴影分离。

**材质**：侧栏与工具条使用半透明 + `backdrop-filter: saturate(180%) blur(30px)`，
不用实色，让内容滚过时保留层次感。

**动效**：`--ease: cubic-bezier(.32,.72,0,1)`，时长 140–180ms，无弹跳。
必须尊重 `prefers-reduced-motion`。

## 5. 布局

```
┌────────────┬─────────────────────────────────────┬──────────────┐
│            │  工具条（sticky 57px，半透明模糊）    │              │
│  侧栏      ├─────────────────────────────────────┤  检查器       │
│  268px     │  内容区 max 1240px，左右 40px         │  400px        │
│  半透明    │                                     │  按需展开     │
└────────────┴─────────────────────────────────────┴──────────────┘
```

| 区域 | 常规 | 窄屏 |
| --- | --- | --- |
| 侧栏 | 268px 固定 | < 720px 收起 |
| 内容区 | max 1240px / 40px 内边距 | 20px 内边距 |
| 检查器 | 400px 并排在右，`position: sticky` | < 1180px 排在内容**之后** |
| draft 目录 | 240–300px 左栏 + 正文 | < 980px 上下排列 |

**关键约束**：

- **默认不是常驻三列。** 检查器按需展开，始终提供关闭与返回路径。
  主阅读区不展示关系大图。
- 所有项目内页面**始终显示项目名称**（工具条面包屑）。
  切换浏览项目不改变 Agent 的操作项目。
- 检查器展开时主内容区收窄但**位置不跳动**；关闭后回到原阅读位置。
- 窄屏时详情排在当前内容之后，而不是抢占开头。

**侧栏结构**：浏览组（项目、对象说明）+ 当前项目组（信息收集、信息整理、
项目材料、变更与决定）。未进入项目时当前项目组显示引导文案。

## 6. 组件

### 6.1 飞书标题链接（最重要的组件）

```
┌──────┬────────────────────────────────┬──────────┐
│ 飞书 │  城市记忆展厅｜项目需求与预算… ↗ │ 查看引用 │
└──────┴────────────────────────────────┴──────────┘
   类型        实际标题（可点击）           独立控件
```

- 点标题 → `target="_blank"` 打开原文，**保留 Yu+ 页面**。已在当前环境验证。
- 点「查看引用」→ 打开本地来源快照详情。**两个动作目的地必须明确，不混用。**
- 标题来自已保存的元信息，不每次请求飞书。
- 标题未知时显示「{类型}材料（标题尚未取得）」，斜体，并保留可辨识地址；**不凭空起标题**。
- 文档改名不新建来源；历史快照保留当时的 `title_at_capture`。
- 同一组件用于对象正文、材料列表、引用面板与已导出成果。

### 6.2 段落依据标签

review 段落标题旁显示精简依据（如「D01 BD 同步信息」），点击展开
draft 对象、使用的版本、原始来源及定位。

- 依据版本与当前版本一致 → 主题色标签
- 不一致 → 状态橙标签 + `· 已变` 后缀，段落整体加浅橙底，
  并给出可读差异说明（「段落基于 v1，当前已是 v2」）+「查看差异」
- 无依据记录 → 中性标签「尚未记录依据」

### 6.3 条目卡（draft）

左侧 3px 主题色边。头部依次为：信息性质标签、主题、适用范围标签、关联成果计数、
复制引用。正文按保存结果呈现：结构化字段用 `<dl>` 两列，正文用 prose，
金额右对齐等宽。来源引用在卡片底部。

### 6.4 采用决定条目

除常规字段外，追加一行说明（决定者 · 理由），用 `--epistemic-adopted-decision` 色。
与「客户原始说法」条目必须**视觉上并列可辨**，不得合并。

### 6.5 检查器

四种详情：来源详情、对象说明、段落依据、完整追溯路径。

- 固定头部（标题 + 关闭 ✕）
- 分节，节标题为 uppercase 小字
- 固定底部「关闭详情 / 返回阅读」
- 追溯路径用 ①②③ 编号表达三级动线：
  **当前段落 → draft 内容 → 原始来源**

### 6.6 状态提示条

浅色底 + 同色边 + 图标 + 文字 + 可选的行动入口。
用于「依据已变化 · 成果尚未同步」「远端有更新」「这是 D15 的同一份数据」等。
**提示条里的行动入口只能是查看动作**（查看受影响段落、在 draft 中打开），
不能是「立即同步」这类写操作。

### 6.7 版本时间线

左侧细线与圆点，圆点颜色表示是否为当前版本。每条：版本号徽标、
时间、变更理由（来自 `changes.reason`）、命令与 revision id、版本对照摘要
（改动 N 条 / 新增 N 条 / 移除 N 条）。

### 6.8 空态

图标（低透明度）+ 标题 + 一句说明 + 可选的下一步。
空态的下一步文案必须是「可以在 Codex 中让 Agent…」，不给页面内按钮
（唯一的例外是「复制创建意图」，它只复制文本）。

## 7. 文案规范

| 情况 | 写法 |
| --- | --- |
| 字段未知 | 尚未记录 |
| 对象无内容 | 这个对象还没有内容 |
| 成果未生成 | 尚未生成，可让 Agent 基于已有对象整理 |
| 来源未被引用 | 材料已保存但尚未被任何对象引用，这不代表未读、无用或出错 |
| 远端未检查 | 尚未检查远端，因此不能说明是否已是最新 |
| 远端检查通过 | 远端未变化（附检查时间与方法） |
| 依据变化 | 依据已变化 · 成果尚未同步（只反映已保存版本之间的差异） |
| 原件丢失 | 外部原件当前不可访问，来源与关联记录仍然保留 |
| 读取失败 | 读取失败：{原因}（{时间}） |
| 不适用 | 本轮只做…；已记录不适用，不是遗漏 |
| 仅有附件 | 该快照只有附件，未提取正文 |

**禁用词**：已登记、读取中、部分读取、已处理、正在被 Agent 处理、待完成、
必填、信息不完整、禁止进入、已通过、待重新确认（无真实记录时）。

## 8. 只读边界（设计的硬约束）

| 动作 | 允许 | 说明 |
| --- | --- | --- |
| 浏览 / 搜索 / 筛选 | ✓ | 仅在已展示范围内 |
| 展开依据、关系、版本 | ✓ | 检查器或行内展开，可关闭返回 |
| 打开来源原文 | ✓ | 飞书标题 → 新标签页 |
| 复制引用 | ✓ | 唯一的副作用，且由用户主动触发 |
| 新建 / 上传 / 编辑 / 删除 | ✗ | 在 Codex 中由 Agent 经 Yu+ CLI 完成 |
| 保存意见 / 确认成果 | ✗ | 用户 review 是阅读并反馈，不是审批流 |
| 页面内聊天 / 评论 | ✗ | 不在产品范围 |

**复制引用的内容约定**：项目名称与 `project_id`、对象编号与名称及 `object_id`、
条目或段落 ID、所看版本号与 `revision_id`，必要时附来源标题与原文片段。
内部 ID 出现在引用里，但不在正文大量显示。

## 9. 实现注意事项

1. **色值只从 `tokens.css` 取。** 组件通过 `--h` 传递语义色，标签样式自动派生。
2. **信息性质、来源类型、阅读主题的映射表放在一处**（如 `themeOf(type_key)`、
   `EPISTEMIC[kind]`），不要在多个组件里重复 switch。
3. **依据变化按段落判断**，不要比较整对象版本号：
   比较该段 `block_lineage` 里 basis 各条的 `revision_id` 与对应对象的
   `current_revision_id`。只有真正不一致才标记。
4. **R05 走特殊路径**：它不可持久化，查询返回 D15 的真实
   `object/revision/item` ID，界面上要说明是同源。
5. **金额以最小货币单位的十进制整数字符串保存**，显示时才转可读金额＋币种；
   未知不显示为零。
6. **日期区分 `date` 与 `range`**，保留精度与时区（如有）。
7. **长列表需要分页或虚拟滚动**（变更记录可能上千条）；
   draft 目录在 23 类以内不需要。
8. **无障碍**：标签不能只靠颜色传达状态（配合文字）；焦点环统一；
   尊重 `prefers-reduced-motion`。
