# Yu+ v0.3.1

修正 Agent 保存排期的指引，避免具体日期只写在文字条目中、没有进入甘特图。

- 主 Skill 明确路由至 D09 保存规则：具体日期点、时刻或完整区间必须使用 time_kind 和 start/end 结构化保存；甘特图自动读取这些字段。
- 一段材料中的多个不连续日期/区间拆成独立条目，不合并成覆盖空档的大区间，也不只保留在 note 中。
- TBC、原文计划和建议排期已有具体日期时同样进入图表，保留真实性质、来源和暂定说明；可绘制不代表已确认。
- 日期未知、仅有相对时间或无法定位到具体哪天的时刻保留为文字，不编造年份、零点、时区或缺失端点。已明确撤销的日期不继续冒充当前排期。
- 修正已有条目时保留稳定身份、来源和历史，避免图表与文字清单重复计数；先改 draft，再更新已有受影响 review。
- 同步 CLI 对象属性、可视化 Skill 和中文审阅稿；页面样式和数据库 schema 3 不变。

## 安装与升级

从[官网](https://cedar-zhang-output.github.io/YuPlus/)复制安装提示词给 Agent，升级到 v0.3.1（包版本 0.3.1）。沿用现有项目目录，升级前备份并停止旧服务，安装后重新启动。中文审阅稿仍不安装或作为 Agent 执行参考读取。

更新 Skill 不会自动改写现有项目。需要修复已有文字排期时，可让 Agent 按新版 D09 规则核对具体项目，保留来源和历史并更新受影响 review。

## 验证

通过真实 draft.apply 和浏览器数据接口保存指引中的 8 条示例：7 条具体时间安排被甘特图选择逻辑收录（包括 5 个 TBC 活动），1 条无日期说明保留为文字。分钟区间时长和日级精度保持正确。5 项 Skill 契约测试、5 项时间轴测试、两份 Skill 格式检查通过。没有操作用户正式项目或真实群聊。
