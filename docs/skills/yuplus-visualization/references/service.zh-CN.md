# 打开正确的服务

## 发现、复用或启动

1. 复用对话或真实模式 Prompt 已明确的数据目录和项目身份，将目录解析为绝对路径。浏览器地址本身不能确定要操作的业务项目。身份不清楚时，先检查已有项目列表，写入前明确目标。
2. 检查已知运行会话、保存的启动输出或已有 Yu+ 标签页。候选端口被占用时，查看监听进程，例如 macOS 可用 `lsof -nP -iTCP:PORT -sTCP:LISTEN`，再请求 `/api/health`。不要为了得到偏好的端口而终止它。
3. 只复用健康、`mode: "live"` 且 `data_dir` 与目标解析路径一致的服务；以返回的 `url`/`port` 为准。演示服务、其他应用或绑定其他数据目录的 Yu+ 服务都不能用来操作本项目。
4. 没有合适服务时，在可持续运行的终端/会话中启动已安装 CLI：

   ```sh
   yu --data-dir '/absolute/project-data' serve --port 0 --json
   ```

   `0` 表示分配空闲本机端口，也可指定已确认空闲的端口。这是前台服务：读取启动 JSON 中的实际地址，并保持该会话运行。源码仓库中若对应环境已安装，可用 `.venv/bin/yu`。通过 `yu --help` 核对接口，不发明 daemon/start/stop 命令。
5. 请求 `GET ACTUAL_URL/api/health`，核对 `ok: true`、`mode: "live"`、目标 `data_dir`、实际 `url`/`port`。再用 `/api/view` 或 `yu --data-dir DIR project list --json` 取得真实项目 ID；`/api/view?project=PROJECT_ID` 读取该项目视图。Shell 路径加引号，查询参数做 URL 编码。

CLI 可初始化新的数据目录，必须有意识地选择目标目录：误选路径得到的健康空数据库，不代表用户原项目丢失。安装或运行环境出错时，查看业务 skill 的环境说明，不改用示例服务。

将新服务的会话/PID、解析后的数据目录和实际地址一起记录。需要停止自己启动的服务时，通过其原终端/会话停止。使用保存的 PID 前，重新核对进程身份、监听和健康检查绑定，因为 PID 可能被复用。不要终止全部 Python/Node 进程或无关服务。使用自动端口的服务重启后，端口可能改变。

## 路由与打开方式

在已验证的基础地址后拼接以下路由，ID 使用实际返回值：

| 目的地 | Hash 路由 |
| --- | --- |
| 项目列表 | `/#/` |
| 对象说明 | `/#/types` |
| 信息收集 | `/#/p/PROJECT_ID/draft` |
| 指定 draft 对象 | `/#/p/PROJECT_ID/draft/OBJECT_ID` |
| 整理与 Review | `/#/p/PROJECT_ID/review` |
| 指定 Review 或共用 Q&A | `/#/p/PROJECT_ID/review/OBJECT_ID` |
| 原始材料 | `/#/p/PROJECT_ID/sources` |
| 变更与决定记录 | `/#/p/PROJECT_ID/history` |

通过可用的 Codex/浏览器打开工具传入完整地址，不关闭或挪用用户的其他标签页。Hash 路由只改变阅读位置，不改变业务状态。复制页面链接不会编码所选历史版本；涉及修改时，要核对页面显示版本并保留其 revision 身份。

页面初始显示“正在读取项目内容”。读取成功后的空项目/空列表，与“无法读取项目内容”是不同状态。后者有“重新读取”，不表示项目无数据。CLI 写入后，用侧栏页脚“刷新页面”或浏览器重新加载读取新内容。同一项目内导航可能复用已加载视图，因此切换路由不保证刷新。

## 演示模式独立存在

`npm --prefix frontend run dev` 启动独立前端演示，默认 7801，可用 `-- --port PORT` 指定端口。健康检查模式为 `demo`，不读取用户数据库。演示来源链接、缓存文本文件都是示例。不能把示例 ID、版本指针、本地演示链接或演示更新 Prompt 用于正式写入。真实服务失败时，不自动切换到演示模式。
