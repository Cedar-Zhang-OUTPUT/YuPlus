# Review 固定结构与生成规则

进入整理场景、编写 Review 或纠正成果结构时读取；已读且仍适用就复用。以下是固定内容结构，不是信息收齐的门槛。

## 先检查，再生成

1. 用户要求“进入 review／整理项目”时，检查下表对应的 draft 和已有成果。复用当前上下文，只补读未知或过期数据；判断是否有实际条目，不能只看对象是否存在。用户只指定某份成果时，限定到该成果及受影响依赖。
2. 对应 draft 已有内容的成果，逐一生成或同步，不能只写 R01。**D09 和 D18 都有内容，就必须生成 R02。** 已符合结构且未变化的成果直接复用，不重复发布版本。
3. 依据不全时，指出缺哪个对象、可通过什么材料或口述补充，并提供“补充后整理／现在按已有信息整理”两个选择。用户已经要求整理，就直接整理可用部分、标明未知，不再二次确认。完全没有依据的成果可暂不生成并说明原因；不得编造事实、资源身份或审查结论。没有 D19 时可以不生成 R04。用户明确要求先拟完全无依据的成果时，可展示固定提纲作为未保存预览。
4. 严格使用下表的栏目名和顺序，在栏目内组织正文；不增设、改名、合并栏目或自拟结构。其他对象只能支持相应栏目，不能扩展章节。缺少信息的栏目保留“暂无已收集信息”或准确的不确定项说明。
5. 选择真实 draft 条目 → `review prepare` → `review publish`。保留实际条目/版本依赖和来源。保存后核对结构、应生成的成果、未知项和仍过期的依赖，再交给用户 review。

## 固定结构

R 对象为一级对象，以下有序栏目是它仅有的二级内容，在 Markdown 中用 `##` 标题表示。说明用于指导栏目正文，不另立标题。

| 一级对象 / type_key | 二级栏目及顺序 | draft 依据与内容边界 |
| --- | --- | --- |
| R01 主策 Debrief / `debrief` | 1. **BD同步信息**；2. **职责边界**；3. **受众**；4. **交付细节** | D01：客户为何现在做、解决什么业务或传播问题。D20，涉及客户决策角色时引用 D10：谁决策、职责边界，两类 draft 分开维护。D06：现场观众、传播受众。D18：策略/主题/体验流/空间/内容/脚本/分镜/技术方案；明确超合同、预算、时间或颗粒度的不做事项。D02/D03 可支持这些栏目，不另增章节。 |
| R02 推进要素 / `advancement` | 1. **时间节点或区间**；2. **交付细节** | D09：日期/区间、回收、合稿和 Review 节点，以及各节点看什么。D18：本轮交付及颗粒度。相关负责人按需引用 D20，不独立维护日期或规格。 |
| R03 创意审查结果 / `creative_review` | 1. **主策策略**；2. **策划预算分配** | D17、D08 及真实审查意见/结论。没有实际审查时可整理已有策略/分配，注明“尚无实际审查结论”，不得声称通过，也不能把 AI 的问题当作决定。 |
| R04 内外部创作者 Brief / `creator_brief` | 1. **评审会结论**；2. **内外部资源**；3. **交付细节** | D23、D19、D18。任务背景在这些栏目内引用 R01 的底层 draft；负责人和回收日期引用 D20/D09。按真实创作者/轮次组织，不虚构资源或合作承诺。 |
| R05 客户 Q&A / 共用 `qa` | **客户 Q&A 问题表** | 展示同一个 D15，不创建第二份 Review 文档。D24 开放性问题仍单独维护。 |

R01 不得额外设置“项目任务”“主题与表达要求”“预算”“风险”“待确认事项”等栏目。相关内容写入四个规定栏目内或对应 draft 对象。结构固定不代表未知事实必须填满。

## 保存与回改

- 信息完整时可每个栏目一个稳定 block。部分信息缺失时，可用一个 block 包含完整固定提纲，依赖实际使用的 draft 条目集合，缺失栏目明确标注未知；不能为缺失栏目随便引用无关条目凑依赖。完全无真实依据时只展示预览，不伪造可保存成果。
- R01—R03 使用 `project` 或真实 `round:<round_key>`；R04 使用 `creator:<resource_item_id>:round:<round_key>`。已有对象和含义对应的 block 保持身份。缺少身份只影响该成果保存，不影响其他整理。
- 事实反馈先改对应 draft。纯表达或旧结构纠正，先把用户指令保存为 draft `expression_guide`，再按真实原因 prepare/publish。有效内容归入固定栏目；在授权纠正范围内移除越界 block、保留历史，不能把旧章节继续附在新提纲后面。
- `expression_guide` 可以指导栏目内的措辞与组织，不能授权任意替换产品固定结构。未变且合规的 block 保留；发布前处理同一成果中已过期的依赖。
