# 策划文档结构（供人阅读）

进入第二场景或整理策划文档时读取对应英文参考，已读不重复。Draft 是贯穿所有场景的业务依据。

1. 查看实际相关条目及既有成果，不重新启用明确删除的对象。有依据的成果按本次范围全部整理；时间和交付已有内容时生成推进安排。信息缺失不阻止推进，不虚构方案或评审。
2. 使用下表固定二级标题及顺序，未知内容简短注明。按真实 Draft 条目准备并发布 Review；每次提交带 `outline_version:2`。先改依据，再改成果。
3. 用户进入第二场景时，同时建立或复用本项目飞书协作文档，按 collaboration 参考配置真实定时任务，无需另行复制导出指令。飞书失败保留本地结果。

| 成果 | 固定二级标题 | 对应 Draft |
| --- | --- | --- |
| R01 主策 Debrief | 项目任务；受众与场景；主策判断；本轮创意任务；边界与判断标准 | D01–D03 任务；D09 受众、D07 场地；D19 策略及 D08 品牌/D10 竞品/D05 历史；D14 交付及 D13 时间/D16 职责；D08/D11/D12/D13/D14/D19 限制与标准，D17/D16 决策边界 |
| R02 项目推进安排 | 本轮交付与分工；时间节点与区间；讨论与评审安排 | D14、D16、D15；D13 甘特图；D19 判断标准、D17/D16 决策角色及 D21 反馈 |
| R03 创意方案 | 核心概念；如何回应项目任务；叙事与体验；视觉与案例参考；深化内容；待讨论事项 | D20 具体方案及任务/策略/受众/资料依据；D25 开放议题、D18 客户澄清 |
| R04 创意评审记录 | 本轮评审对象；反馈与判断；取舍与结论；下一轮修改 | D21 指向确切方案及历史版本；实际结论更新 D20/D19 和决策历史；修改任务关联 D14/D16/D13 |
| R05 客户 Q&A | 客户 Q&A 问题表 | 同一个 D18，不复制维护 |

R01/R02/R04 使用 project 或 D14 已有的真实 round 范围；R03 使用 proposal:<D20条目ID>。编号只是展示序号，命令使用稳定的 type_key 和对象身份。

D19 保存策略与判断标准，D20 保存具体方案。补图或改写同一方向更新原条目，新方向创建新条目。深化模块按项目选用：脚本、分镜、关键视觉、声音、展区、动线、展项、互动、传播触点。只将明确选用的案例研究作为项目依据，案例库保持远端使用原则。

结合内容和时间关系，区分独立方向、同方向迭代、布局研究与历史参考。不同文件或日期不等于不同方案。保留历史版本和来源；关系不明就明确标注，不擅自合并，也不把全部材料写成当前并列方案。既有归类有误时先改 Draft，再重新生成 Review。

## 内容职责

- **主策 Debrief：**说明任务、受众、主策判断、创意问题与边界。“本轮创意任务”写创意要解决什么；详细交付清单、设备和人员分工归入推进安排。
- **项目推进安排：**维护交付、负责人、时间和评审安排。引用相关创意判断，不重复整份 Debrief。
- **创意方案：**只讲本方向。“深化内容”补充叙事体验、视觉参考之外的具体发展，不重复前文。“待讨论事项”只列本方向特有的问题和影响。项目共性开放议题保存在 D25，客户澄清保存在 D18；相关处引用，不向每个方案复制同一问题表。
- **创意评审记录：**针对当时的确切版本记录实际反馈、决定和修改，不复述完整方案。

每个实质事实或清单有一个主要位置；其他章节只补充相关影响或简短引用，保留不同轮次的真实差异。共用的读取/权限限制说明一次并写清范围，只在确有不同影响时补充。固定章节缺少依据时一句说明，不填充套话。模块字段用“动线、展区、关键视觉”等自然名称，不展示 `journey:`、`zones:` 等字段键。发布前通读本次全部成果，检查重复段落、重复问题表和放错章节的细节。

修改事实先改所属 Draft；纯措辞先保存成果编写依据，再按真实 cause 更新 Review。历史版本不重写；旧结构在用户要求整理时迁移。协作者建议不等于决定，最后编辑者不等于作者或决定人；反馈保留原目标版本。
