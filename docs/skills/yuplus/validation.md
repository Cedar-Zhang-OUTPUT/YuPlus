## 行为对照

编写前做了不提供新 Skill 的四场景方案测试。已有 Agent 能自然遵守部分规则，例如预览不写库、缺失预算不必阻止收录；不能把这些原本正确的行为记成 Skill 修复。观察到的不足包括飞书更新优先提出浏览器读取、建议下一步前倾向重读较多内容，以及未形成产品要求的三项结尾。

提供 Skill 后做了以下验证，严格区分实际操作和文字方案：

| 场景 | 验证方式 | 结果 |
| --- | --- | --- |
| 已有 Debrief 预算段缩短并保存、含义不变 | 独立 Agent 读取 Skill，并在隔离的模拟数据目录实际调用 CLI | 成功按 source → expression_guide → prepare → publish 执行并回读；未改预算事实 |
| 同一会话只要措辞预览 | 仅方案评估 | 提出复用已读上下文、不写入，明确仅展示预览 |
| 只收纪要，预算和日期未知 | 仅方案评估 | 提出只收来源，提示可开始整理，不强制字段齐全 |
| 飞书有更新但认证不可用 | 仅方案评估 | 不声称已同步、不猜 revision；提出恢复登录或导出物路径 |
| 已知目标，用户问下一步 | 仅方案评估 | 复用已知信息，提出读取已有场地 PDF 的具体建议，不自动执行建议 |

真实试验使用仓库演示生成的隔离项目，未读取个人项目或真实客户内容，未访问飞书和其他网络服务。Agent 只按 Skill、相关参考和查询工具完成请求，没有读取应用源代码或现有 JSON 示例来代写操作。

实际写入顺序和回读结果：

1. 读取预算及成果，按需查列表确认编写依据是否存在和成果 scope。
2. 收录模拟用户的原话。
3. 新建仅针对预算段的 `expression_guide`。
4. `review prepare` 获取真实预算/编写依据版本与可使用原因。
5. `review publish` 保留原成果及段落身份，保存为第 3 版。
6. 回读确认预算仍为第 2 版、人民币 60 万元，只有表达发生变化；结束答复包含真实读取、保存内容和具体下一步。

实测还发现两个需要解释的查询行为，已同步补充到英文参考及中文译文：review show 不提供 scope_key，必要时用 review list；新编写依据的过期影响列表可能为空，应查看 available_causes 的 eligible_blocks，而不是因此放弃用户要求的改写。

## 场景定义修正

上述方案评估发生在场景定义澄清前，其中“收集只写来源”的理解不适合作为一般规则。现已按用户澄清修正：信息收集对应 draft，读取材料后可将实际获取的信息写入 draft；信息整理对应 review，由 AI 根据已有 draft 组织、改写成果。只有明确要求“仅存档原件”时才限定为只写来源。英文 Skill、中文译文、对象说明及 README 已同步；原有 CLI 实测结果不等于对修正后收集行为的重新实测。

## 尚未验证

这是一次实际成功试验和四个方案场景，不能代表所有模型、项目与上下文条件下的表现。没有实测真实飞书登录/文档更新、PDF/媒体解析、跨机器 Skill 安装、长对话压缩后的恢复，以及多段成果在 Agent 操作中的保留行为。CLI 已有分页、幂等、冲突和依赖等自动测试，但不等同于 Agent 在这些场景中都已通过实测。
