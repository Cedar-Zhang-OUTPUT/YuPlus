# Yu+ 真实数据接入实施记录

依据：已授权实施的 [前端交接](../../design/2026-10-16-frontend-integration-handoff.md)。沿用最终视觉与交互；不改用户未跟踪的 specs.zip。

## 最小接入方案

- Python 标准库提供 `yu serve`、本机只读 API 和静态页面，复用既有 SQLite/文件池；Node 只用于明确标识的模拟预览和前端测试。
- 视图适配读取已保存业务结构，保持历史快照及稳定身份，禁止把模拟数据作为业务写入。
- API 全局仅列项目与目录；项目内容按 project_id 读取，服务内一致性快照。来源资产仅以登记身份读取，业务数据通过 CLI 写入。
- 前端保留布局，改为显式真实/模拟模式、真实刷新/加载失败、权威条目依据状态、真实来源和资产、实际项目 Prompt。
- 本地完整导出包保留所有 review 实例、共用 Q&A、来源追溯和版本清单；Agent 经飞书 CLI 新建文档并回读核验。外部认证失败保留导出包，不冒充成功。
- 更新业务 Skill，并另建可视化使用 Skill 与中文说明，指引按实际服务/路由/控件工作。

## 实施与验收顺序

1. 接入只读网关、视图与真实资产；以隔离目录测试项目隔离、历史及依据、Host/Origin、路径和只读边界。
2. 接入页面运行时与真实 Prompt；保留模拟模式并运行既有前端测试；检查未知依据、日期精度与金额字段。
3. 完成完整导出准备及测试；核对飞书 CLI 实际认证/能力后做外部验证或记录具体阻碍。
4. 在隔离真实业务数据中走创建项目、材料、draft、review、浏览、修改依据、差异、更新及导出准备。
5. 按最终行为补 Skill、安装/启动说明，检查 wheel 包含前端静态资源，完成独立审查。

文档不取代执行证据；最终验证结果记录在集成验收文档中。
