# Yu+ 前端页面与对象语义设计

页面讨论稿 v0.2 · 2026-10-13

后续信息需求以[可视化界面信息展示 Spec](2026-10-13-yuplus-visualization-information-spec.md)为准。本文保留早期浏览草图及验证记录，其中的布局、组件和排布不作为正式 UI 设计约束；尚未实现的能力以新稿说明为准。

前置依据：已确认的《Yu+ 对象关系与展示对照表》。本稿设计浏览交互，不实现业务后端、CLI 或正式 Skill。配套草图中的展厅项目、预算与交付正文都是示例数据；真实《YU+ Dev》链接仅用于验证标题链接的打开行为，不作为示例展厅的材料来源。

## 1. 页面结构

全局：项目列表。

项目内：Draft／信息收集、Review／信息整理；材料与历史作为项目内辅助入口。

辅助查看：对象详情、来源详情、关联对象及成果、历史版本。宽屏按需在右侧展开详情；窄屏将详情排到当前内容前方，保留关闭和返回路径。默认不常驻三列，也不在主阅读区展示关系大图。

所有项目内页面始终显示项目名称。切换浏览项目不改变 Agent 的操作项目；交给 Agent 的对象引用必须包含项目标识和稳定对象标识。当前浏览页签不等于项目工作阶段。

## 2. 项目列表

- 行列表展示名称、客户/简述、最近实际变更摘要和更新时间；按最近更新排序，可按名称搜索。
- “当前项目”“过往项目”是浏览分组；项目结束由用户在 Codex 中决定、Agent 写入，页面不根据日期猜测。
- 不展示信息收集百分比、必填完成率或通关流程。
- 点击项目进入上次浏览位置；第一次进入默认打开 draft。
- “新建项目”仅作为在 Codex 创建的引导：显示可复制的创建意图，不在页面提交业务写入。未来如果宿主存在已验证的带上下文唤起能力，可以替换手动复制；不假定网站能自行发送 Codex 消息。
- 没有项目时给出简短空态和创建入口，不预建唯一工作空间项目。

## 3. Draft／信息收集

### 3.1 布局

- 页签下方为可搜索的对象目录与所选对象正文。
- 目录按阅读主题分组，仅改变展示，不新增业务对象：背景与需求、研究与资料、计划与协作、判断与决定。
- 默认优先展示已有内容的对象；完整对象目录可展开，不把未出现对象渲染为 23 张空卡。
- 首次进入可默认选择最近更新的对象；草图选择“交付细节”，便于查看先因后果关系。
- 对象标题旁可展开“对象说明”；用户需要时查看简短职责，Agent 的完整语义不强塞入阅读页面。

### 3.2 对象内容按类型呈现

| 类型 | 对象例子 | 主要呈现 |
|---|---|---|
| 正文 | BD 同步信息、主策策略、评审结论 | 分段正文、明确的来源/判断标识、内联引用 |
| 结构化信息 | 预算、受众、职责、时间 | 可读字段、对照条目、节点；有数据才出现对应视图 |
| 材料集合 | 场地资料、品牌资料、客户 Brief | 标题链接、文件预览、图片集合、关联提取条目 |
| 清单 | Q&A、风险、资源 | 按项查看问题、依据及关联内容 |

同一个对象可以同时包含正文、字段和材料引用，不必强制归入单一渲染类型。

### 3.3 查看路径

每个有依据的条目显示“来源”引用；点击引用展开右侧来源详情，保留原对象阅读位置。

“关联成果”显示哪些 review 段落使用此内容，点击跳转到对应成果和段落；可返回原对象。来源详情也能查看“用于哪些对象”，形成双向追溯。

用户可以复制对象/条目引用，在 Codex 中提出修改。没有直接编辑、批准、删除、上传按钮，也不显示 Agent 读取状态。

## 4. Review／信息整理

- 左侧列出五类成果；主体按文档阅读方式展示已生成的内容，不把每段都拆成独立卡片。
- 页头显示成果标题、版本、更新时间，以及已有审核记录（若存在）。不设置“必须审核才能继续”的按钮或门槛。
- 段落旁显示精简的依据标签，例如“交付细节”。点击后展开 draft 对象、使用的版本、原始来源及定位信息。
- 追溯完整路径是“当前段落 → draft 内容 → 原始来源”。关系面板中的“查看 draft”直接导航到具体对象/条目。
- 修改通过复制段落引用交给 Codex。反馈会先进入 draft（包括纯表达要求），再由 Agent 更新成果。
- “依据已变化”只在可验证的依赖版本不一致时出现，可查看差异；不等于系统知道 Agent 的工作进度。
- 若尚无成果，说明“可让 Agent 根据现有材料整理”，不显示材料不足或锁定入口。
- R05 展示同一个 Q&A 集合，不能创建 review 专用问题记录。
- 导出飞书属于写操作，由 Agent 经 CLI 执行；页面可以复制导出意图，并展示已导出的文档标题、成果版本及时间。

## 5. 材料、来源与历史

项目材料入口聚合飞书、本地文件和用户补充，可按类型浏览；保持与对象中引用相同的来源身份。

来源详情展示：标题、来源类型、原文入口/本地预览、已保存版本与时间、引用片段或实际可用定位，以及关联对象。原材料与用户后来的决定分开显示。

历史入口以变更事件为主，正式决策可单独筛选；每条记录关联受影响 draft 和 review。不是聊天全文备份，也不是 Agent 的执行过程日志。

## 6. 飞书标题链接

### 6.1 展示约定

以统一的标题链接组件展示：类型标识＋实际文档标题＋外部打开标识。点击标题打开原文；独立的“查看引用”控件打开本地来源详情，两种动作不要混用。

同一组件可用于对象正文、材料列表、引用面板及已导出成果。支持一个对象引用多份飞书材料，也支持正文中的多个内联引用。

标题来自 Agent 经飞书 CLI 实际获取的元信息，并随来源记录保存。页面读取本地缓存，不在每次渲染时调用飞书。已有元信息时，Agent 只需写入来源引用，前端自行用统一组件显示标题。

仅保存裸链接、尚未成功获取元信息时，不编造标题：显示“飞书文档”及可辨识的地址提示；已取得的旧标题在后续访问失败时保留，并允许查看实际地址。文档改名不新建来源，更新同一来源的标题元信息；保留历史快照中的旧标题。

来源身份依据提供方、资源类型和稳定标识确定，不依据标题；规范化普通分享参数时不能丢失块定位信息。文档来源可以复用，具体引用仍保留各自的段落锚点。

### 6.2 打开约定与验证边界

产品目标：在 Codex 内置浏览器中点击飞书标题，在该内置浏览器的新标签页打开，保留 Yu+ 原页面。普通网页侧首先采用真实链接与新标签目标，不把打开动作替换成页面内嵌飞书。

最终去向由宿主浏览器处理。用户已在当前 Codex 环境中验证点击飞书标题可以在内置浏览器的新标签页打开，后续正式页面沿用此交互并作回归检查。CLI 身份与浏览器登录状态不能混为一谈：能通过 CLI 读到文档，不保证浏览器已登录。

验证结论：用户已验证可用（2026-10-13）。此前 Agent 的自动化检查没有观察到新标签，属于该次检查未能确认；后续用户实际验证已补足结果，不再列为未解决的能力问题。这不代表完整 Yu+ 应用已经实现。

交互草图中的虚构来源仅演示标题和本地引用详情；真实《YU+ Dev》另设链接样例，避免把真实文档冒充示例项目材料。

## 7. 让 Agent 理解对象属性

保留原飞书文档“属性描述”中的业务语义，不只给 Agent 一个字段名和数据类型。

建议未来的 Yu+ Skill 使用两层组织：

1. 主 Skill：介绍场景、按需读取原则、CLI 操作方式、先 draft 后 review、来源与决定的区分及回复规范。
2. 对象参考说明：按稳定对象标识提供定义，Agent 在当前任务涉及该对象时按需读取；不要求每轮加载全部 23 类。

| 每个对象的属性 | 指导 Agent 回答的问题 |
|---|---|
| 名称与业务含义 | 这是什么，记录的对象是什么？ |
| 可能来源 | 应从什么材料、角色、对话中获得信息？ |
| 用途与承接 | 在哪个场景帮助谁完成什么，供哪些对象或成果引用？ |
| 内容范围 | 哪些信息应放在这里？ |
| 归属边界 | 哪些内容应引用其他对象，避免重复保存？ |
| 判断与确认规则 | 原话、事实、推测、建议、正式决定如何区分？ |
| 缺失或冲突的处理 | 如何如实保留并给出补充建议，而不是阻断流程？ |
| 更新影响 | 改动后应检查哪些对象或成果，哪些引用需要更新？ |
| 正反例 | 什么属于正确归类，什么属于常见误用？ |

示例：D18 交付细节

- 含义：本轮交付约定，覆盖轮次、交付物、颗粒度、格式规格、数量、使用限制、外部依赖及不做范围。
- 来源：客户 Brief、招标文件、BD 同步、会议记录，以及用户明确的本轮约定。
- 用途：供 Debrief、推进要素、创作者 Brief 等引用，帮助各方理解本轮任务边界。
- 边界：日期引用 D09，负责人引用 D20，预算引用 D07/D08；原始材料不因约定变化而改写。
- 缺失：可建议用户通过会议纪要或口述补充，不要求填满才能整理。
- 冲突：同时保留原始要求和当前采用口径，记录改变的依据；不将内部决定改写成客户原话。
- 更新：用户从 review 修改交付要求时先改 D18，按适用轮次/创作者定位，再检查 R01、R02、R04 的具体引用。
- 正例：将“本轮只交概念脚本”记录到对应轮次，并保留用户决定。
- 反例：仅改创作者 Brief，draft 仍要求成片；或把单个创作者的要求覆盖成全项目要求。

对象说明的内容基线就是已确认的 23 类对象表及原文属性。页面的简短“对象说明”应从同一套定义派生，避免 UI 和 Skill 对同一个对象解释不同。具体配置格式和 CLI 查询语法在后续接口设计中确定，本轮不虚构可执行命令。

## 8. 草图评审路径

打开项目列表 → 进入“城市记忆展厅” → 在 draft 查看交付细节 → 打开来源引用 → 查看关联成果 → 在 review 查看创作者 Brief → 点击依据回到 draft。

也可切换预算对象，查看事实、BD 转述与用户决定的区别；切换其他示例项目检查项目隔离；查看没有成果的项目空态。

本轮确认信息布局与浏览路径后，再细化视觉样式和实施计划。草图不代表真实材料已入库、已调用 CLI 或已导出飞书。

用户反馈：当前草图的视觉风格不符合预期，不作为正式视觉方向；暂不调整风格，等待用户后续指导。草图只用于说明浏览与关联交互，不据此缩减对象范围，也不将本次反馈视为对所有页面布局的正式批准。

已在 Codex 内置浏览器检查：项目列表进入 draft、展开来源、跳转关联 review、段落依据展开、回到 draft，以及切换至另一个项目的独立空态。草图重点展开六类代表性 draft 对象和五类 review 入口；完整 23 类目录与正式内容渲染留待页面方案确认后实现。
