## 完整链路与界面

`test_monitor_e2e.py` 使用真实 CLI 子进程、SQLite、文件目录及 HTTP 服务，只替换外部飞书可执行文件。模拟消息按“预算100万 → 确认 → 预算60万”的时间顺序形成两条带来源的决定，并将已有 review 更新到第二版。重复执行保留两条决定，不产生重复变更；实际运行备份/恢复并确认恢复副本暂停。

Codex 内置浏览器另行打开隔离服务，确认项目列表监控摘要、draft/review 共用监控区域、真实 `openChatId` 群链接、保存的运行记录、更新后的60万成果可见。未绑定真实调度时明确显示“待接通定时任务”。复制按钮显示成功反馈；按钮生成内容的项目/目录/监控范围由自动测试校验。测试服务和浏览器页已关闭，用户原有59573服务及正式数据未修改。

独立代码复查发现并修复：群链接参数不匹配、相同正文遗漏较新编辑水位、话题上下文丢失/推断、无关旧消息复查阻塞、时钟回退产生无法续跑的窗口。相关回归包含在上面的160项测试中。

## 明确边界

没有读取真实群、创建真实宿主定时任务或发布新版本。以上验证不代表真实飞书权限、无人值守执行环境或实际定时唤起已验收；需用户指定群后完成实际绑定与一次定时运行。当前 v0.1 下载包不会随源码分支更新。

调度由 Codex 原生工具驱动，CLI 只保存回执和同步账本，不启动模型或后台调度器。独立 CLI 无法认证 Codex 宿主身份，Skill 要求定时运行前通过宿主工具核验主机、会话、实际任务范围及数据目录；复制/迁移数据库不能当成沿用旧宿主回执的授权。

增量读取重叠五分钟，复查最近24小时已知消息、持续检查已发现话题、每日复查当前对象引用的消息。不保证发现任意迟到、很旧且未被引用消息的全部修改或此前不可见的旧话题；API 不可见的历史及无法读取的附件不算已阅读。消息缺失不推断为撤回。
