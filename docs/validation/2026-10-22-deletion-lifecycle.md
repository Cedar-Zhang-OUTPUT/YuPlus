# 删除链路验收（v0.3.12）

补齐 `draft/review/source delete` 与 `restore`，JSON 输入契约、按需查询工具、英文执行 Skill 及中文审阅稿同步更新。数据库沿用 schema 3 的 archived_at 和不可变版本，无迁移。

- draft 删除复用原有子目删除逻辑：已采用决定必须有新决定记录，资源字段引用须先处理；删除后输出受影响对象，旧版本可查。
- Review 删除复用逐段因果校验；删除最后一段保存空版本并隐藏成果。已失效创作者/轮次可清理旧成果，但不能据此绕过新内容的范围校验。
- 来源删除保留文件池、原文件及既有引用；停止后续远端检查，并使在途旧检查回执失效。
- 普通列表/导出排除已删除根对象；历史追溯保留，来源详情标注删除状态，旧成果路由仍保留页面框架。
- restore 重新启用原身份；来源内容恢复展示，draft/Review 保留删除后的空版本。恢复业务内容需读取旧版并按正常依据写回，不能复用已消费的删除原因。

验证使用隔离临时项目，未修改用户项目。全量后端 193 项通过；随后补充的失效创作者范围清理测试与 8 项生命周期测试共 9 项定向回归通过。前端/官网 58 项通过，两份 Skill 格式校验通过。覆盖改写/删除、最后一段、历史和原字节保留、备份、软删除可见性、重新启用、幂等、过期版本、跨项目、决定记录、悬空资源引用及旧原因重用拒绝。

发布前另以正式安装包执行 v0.3.11 → v0.3.12 隔离升级：核对项目保留、schema 3、两份 Skill 与新增参考文件、真实安装 CLI 的 draft 删除/重新启用及历史查询、服务启动与静态资源一致性。真实群聊和宿主定时任务不属于本次测试。
