# Yu+ 对象属性与成果关系

这是业务含义参考，不是建档清单。只读本次涉及的条目；精确写入字段通过 `scripts/inspect_contract.py` 查询已安装版本。本文业务属性来自随应用维护的 `object-types.json`；版本不一致时用 `yu types show --type TYPE --json` 核实。

所有业务对象都允许未知、不适用和稍后补充。下游列表表示可能关联，不代表每次都必须建立全部关系。展示方式是产品语义设计，不意味着当前已有可用前端。

## Draft 属性

source 保存取得的材料及版本，draft 保存带依据的项目内容。文件、图片和视频在来源资产中保存；draft 引用对应来源版本、资产和实际定位。不要把一份上传文件误当成已经分析完毕的结构化内容。

### D01 BD 同步信息（`bd_context`）

- 含义与边界：项目背景、客户为何现在做、目标与核心问题、决策标准和偏好；区分客户原话、BD 判断与用户采用口径。
- 可能来源：BD 口述/文档，D02、D03、D14；缺口关联 D15。
- 展示语义：分主题正文与原话引用，标明信息性质。
- 可能影响：R01 主策 Debrief、D17 主策策略。

### D02 客户原始 Brief（`client_brief`）

- 含义与边界：原始材料引用、版本，以及从中提取的需求条目；用户纠正单独保存，不伪装成客户原文。
- 可能来源：客户文件或飞书文档；条目关联 D01、D06、D07、D09、D18 等。
- 展示语义：原件预览与需求条目对照。
- 可能影响：R01；其他 draft 对象的证据。

### D03 招标文件（`tender_documents`）

- 含义与边界：原件引用、版本、范围/交付/评审等要求及差异说明。
- 可能来源：招标原始材料；与 D02、D01 对照。
- 展示语义：文件预览、要求清单和原文定位。
- 可能影响：R01；D09、D10、D18 等。

### D04 场地资料（`venue`）

- 含义与边界：图纸、照片、地址等材料集合，以及有依据的场地条件；未核实尺寸不填成事实。
- 可能来源：本地/飞书材料、可核实公开资料。
- 展示语义：图片/图纸预览与场地条件说明。
- 可能影响：D17、D22；R01/R04 按实际需要引用。

### D05 甲方客户品牌资料（`brand_assets`）

- 含义与边界：品牌材料集合、定位、文化资产、核心信息与视觉规范；资产使用条件关联 D18。
- 可能来源：品牌文件、客户公开资料。
- 展示语义：材料集合、视觉预览与主题摘要。
- 可能影响：D17；R01/R04 按需引用。

### D06 受众（`audience`）

- 含义与边界：现场观众与传播受众分别记录；画像、需求、触达点及依据。
- 可能来源：D01、D02、D14；AI 假设单独注明。
- 展示语义：两类受众卡片或正文，附来源。
- 可能影响：R01、D17。

### D07 总预算区间（`budget_range`）

- 含义与边界：客户预算、期望区间、币种及口径；保留不同说法和本轮采用值。
- 可能来源：D01、D02、D03、D14，用户明确决定。
- 展示语义：预算字段、来源说法对照、当前采用口径。
- 可能影响：D08、D16、D22；R01/R03 按需引用。

### D08 策划预算分配（`budget_allocation`）

- 含义与边界：投入重点、克制项、分配建议与已采用分配；预估与报价分开；相关实际审查意见。
- 可能来源：D07、D16、D19、D23，用户评审意见。
- 展示语义：可编辑对象的只读分配表与说明，来源及决定记录。
- 可能影响：R03 创意审查结果、D17。

### D09 时间节点或区间（`milestones`）

- 含义与边界：事件、日期/区间、对应交付及 Review 看什么；倒排结果注明依据。
- 可能来源：D02、D03、D14、用户安排，关联 D18/D20。
- 展示语义：节点清单；信息足够时可用时间轴或甘特视图。
- 可能影响：R02 推进要素、R04；其他成果直接引用日期。

### D10 客户关键决策节点（`client_decisions`）

- 含义与边界：客户侧谁决定什么、哪些事项待客户确认、双方决策边界。
- 可能来源：D01、D03、D14；决策标准引用 D01。
- 展示语义：决策角色与事项清单。
- 可能影响：R01、R04；相关日期引用 D09。

### D11 合作类型（`cooperation_type`）

- 含义与边界：竞标、直接委托、前期咨询、在执行追加等类型及依据。
- 可能来源：D01、D02、D03。
- 展示语义：简单选项及补充说明。
- 可能影响：D16、D17、D18；R01 按需引用。

### D12 竞争对手分析（`competitor_analysis`）

- 含义与边界：已知竞争对象、公开作品与研究判断；未经核实的名单和推测单独标明。
- 可能来源：D01、D03、公开资料。
- 展示语义：对手卡片、作品引用与分析正文。
- 可能影响：D17；R01/R03 按需引用。

### D13 客户历史合作方与过往项目（`client_history`）

- 含义与边界：历史项目、合作方、表达方式及来源，不直接推定本次偏好。
- 可能来源：客户资料、公开记录、可核实项目资料。
- 展示语义：案例条目、媒体预览与分析。
- 可能影响：D01、D17。

### D14 与甲方的会议纪要（`client_meetings`）

- 含义与边界：原始纪要/转写引用、会议时间，以及客户原话、意见和实际决定的提取。
- 可能来源：飞书或其他真实会议材料。
- 展示语义：纪要正文/来源预览、议题引用；相关定位按实际获取能力保存。
- 可能影响：向多个 draft 对象提供证据；可由 review 追溯。

### D15 客户 Q&A 问题表（`qa`）

- 含义与边界：问题、影响对象、跟进人、答复、依据与状态；答复落实到对应对象后保留关联。
- 可能来源：所有对象发现的缺口与用户问题。
- 展示语义：问题清单及详情、答复与影响对象。
- 可能影响：R05 展示同一问题表；其他成果引用。

### D16 立项评估结果（`project_assessment`）

- 含义与边界：档期、资源、供应商、预估投入及价值匹配判断；建议与正式评估区分。
- 可能来源：D07、D09、D19、D22，用户评估。
- 展示语义：分项评估正文与判断依据。
- 可能影响：D21、D23、D17；R01/R03 按需引用。

### D17 主策策略（`lead_strategy`）

- 含义与边界：本轮目标、策略、调研判断、方向候选与取舍理由；保存已有策略及实际审查意见，不要求收集阶段必须完成创意策划。
- 可能来源：D01、D04—D08、D12、D13、D16、D23。
- 展示语义：分主题策略正文、研究引用、方向条目与取舍依据。
- 可能影响：R03；R01/R04 按需引用。

### D18 交付细节（`deliverables`）

- 含义与边界：轮次、交付物、颗粒度、格式/规格、数量、限制、外部依赖和不做范围；日期统一引用 D09。
- 可能来源：D01—D03、D14、用户约定；关联 D05/D19。
- 展示语义：交付清单、规格和边界说明。
- 可能影响：R01、R02、R04。

### D19 内外部资源（`resources`）

- 含义与边界：人员/机构、能力、作品依据、档期条件，以及候选/已核实可用/已确认参与的区别。
- 可能来源：团队与合作资料、D01、D16；任务引用 D20。
- 展示语义：资源卡片、作品与参与情况。
- 可能影响：D16、D17、R04；D08 按需引用。

### D20 职责边界（`responsibilities`）

- 含义与边界：主策、专业负责人、BD 接口与内部拍板人，以及任务职责和协作接口；建议分工与实际承接分开。
- 可能来源：用户明确安排、D19、相关会议记录。
- 展示语义：人—职责—任务清单。
- 可能影响：R01、R02、R04；日期/规格引用 D09/D18。

### D21 项目评级（`project_rating`）

- 含义与边界：A/B/C 等评级、理由及确认依据；建议评级与正式评级区分。
- 可能来源：D16、D23、用户明确判断。
- 展示语义：评级及理由，关联决定。
- 可能影响：资源投入和策略判断；R03 按需引用。

### D22 风险点（`risks`）

- 含义与边界：风险线索、触发条件、影响、应对建议、待核实事项及接受/处理决定。
- 可能来源：各对象与材料，用户判断。
- 展示语义：风险清单、来源、影响对象及处理说明。
- 可能影响：D16、D17、D23；R01—R04 按需引用。

### D23 评审会结论（`assessment_decision`）

- 含义与边界：实际立项评审结论、Go/No-Go、补材料/调整交付/重新评估等决定；不与创意审查混用。
- 可能来源：真实评审记录、用户明确结论，关联 D16/D21/D22。
- 展示语义：结论正文、行动项及决策历史。
- 可能影响：R04、D17；其他成果按需引用。

## 内部编写依据：expression_guide

不是第 24 类业务对象。作用是把用户对成果的措辞、结构、强调、删减要求先记入 draft，再更新 review。scope_key 为 `review:<review_object_id>`；条目指向具体 review 与 block_ids，保存 instruction、intent 和用户指令的来源证据。intent 使用 rewrite / structure / omit / retain。全文标题或顺序要求可指向 `*`；具体段落只指向实际受影响段落。

编写依据不能替代事实依据。业务内容改变时，先改相应业务对象；只有表达改变时，不要为了制造 cause 修改预算等业务事实。

## Review 成果及回改位置

成果由 Agent 根据 draft 重新组织成连贯内容。每个段落保留实际 draft 条目/版本依赖；不是另一套独立维护的业务数据。复用 R01 的表达时，R04 仍需依赖底层 draft。

| 成果 | type_key | 依赖与内容 | 用户要求修改时先改哪里 |
| --- | --- | --- | --- |
| R01 主策 Debrief | `debrief` | D01 背景目标、D02/D03 需求依据、D06 受众、D10 客户角色、D20 内部职责、D18 交付边界；其他按实际内容引用 | 目标改 D01，受众改 D06，客户角色改 D10，内部分工改 D20，交付改 D18；原文解读错误改对应提取条目 |
| R02 推进要素 | `advancement` | D09 时间、D18 交付；负责人引用 D20，问题引用 D15 | 时间与 Review 节点改 D09，规格与颗粒度改 D18，负责人改 D20 |
| R03 创意审查结果 | `creative_review` | D17 策略及实际审查意见、D08 分配及实际审查意见；按需引用 D07/D16/D21/D22 | 策略改 D17，分配改 D08，其余事实回到相应对象；无实际结论时保留待讨论，不伪造通过 |
| R04 内外部创作者 Brief | `creator_brief` | D23 立项结论、D19 资源、D18 交付；背景/受众/策略来自 D01/D06/D17，职责来自 D20，日期来自 D09 | 按所改内容回到对应对象；围绕具体资源和交付轮次组织，不复制公共事实 |
| R05 客户 Q&A | 展示 `qa` | 使用 D15 的同一对象 | 更新 D15；答复涉及事实时同步相应业务对象，不另建一份 review Q&A |

R01/R02/R03 可使用 scope_key=`project`；确实按已有交付轮次组织时使用 `round:<round_key>`。R04 使用 `creator:<resource_item_id>:round:<round_key>`。创建前查询实际契约与已存对象，复用真实轮次/资源身份；不能为了绕过因果校验更换 scope。缺少具体成果所指向的身份时只澄清该目标，仍可继续收录和整理其他信息。

D10 客户角色与 D20 内部职责分别维护；D09 日期与 D18 交付规格分别维护。D23 是实际立项评审结论，R03 是创意审查成果。对象属性中的可能来源和下游关系不等于必须补齐的业务字段。
