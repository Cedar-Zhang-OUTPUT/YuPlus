    它是什么

    Codex 负责思考，
    Yu+ 负责记住。

    Yu+ 不是聊天机器人，也从不自己调用模型。你和熟悉的 Codex Agent 对话；Yu+ 给这个 Agent 一套规则、一份记录和一扇窗。

    1. 01

      你

      在 Codex 里说话：发飞书链接、丢文件、说明哪里变了。

    2. 02

      Codex Agent

      读取飞书、本地文件与群聊；理解、整理、写作。

    3. 03

      Yu+

      $yuplus
      两份 Skill：内容放哪里、什么算事实、先改什么。
      yu CLI
      保存前校验版本、证据与因果，拒绝跳过 draft 的改写。
      SQLite
      一份本地数据库 + 按 SHA‑256 寻址的文件池，只追加。
    4. 04

      只读页面

      在 Codex 内置浏览器里浏览、追溯任意段落，复制引用交回对话。

    工作方式

    两个场景，随时往返。
    没有门槛。

    不必等资料齐全。收集进 draft、整理成 review，任何时候都可以补材料、提修改。没有完成度进度条，也没有审批关卡。

    source

    原始材料

    飞书文档、本地文件、你的口述、指定的项目群。保存身份与版本，不把上传当成已分析。

    →

    draft · 24 类

    信息收集

    Agent 把读到的信息放进对应对象——预算、受众、场地、风险——每一条都标注来源与性质。

    →

    review · 5 类

    信息整理

    基于已有 draft 写成固定栏目的成果：主策 Debrief、推进要素、创意审查、创作者 Brief、客户 Q&A。

    你的反馈 → 先改 draft → 再同步每个受影响的 review。直接改写 review 会被拒绝。

    每条信息都标明性质

    推测永远不会伪装成客户原话。颜色本身就能读懂。

    • 原文陈述

      可以回到原文定位。

    • 用户补充

      主策补充，不是客户原文。

    • 转述

      经他人转述，可能有偏差。

    • 假设

      尚未确认，不作事实依据。

    • 建议

      是提议，不是正式决定。

    • 采用决定

      已采用的口径，附依据。

    循环之外

    为真实的比稿节奏而做。

    ◷

    群聊监控

    绑定你指定的飞书项目群，默认每 60 分钟通过 Codex 原生自动化检查。首次读取全部可访问历史并按时间处理；旧消息与较新的决定对照，不覆盖当前结论。

    ⌕

    找案例

    在你登记的每个案例库（飞书文件夹与网站）和公开网络中检索，读真正的案例页面，把入选案例和适配理由排在飞书画板上。新一轮是 v2，同轮补充沿用当前版本。

    ↗

    导出飞书

    用当前成果创建可读的飞书文档，回读核验后才报告导出成功。

    ⧉

    备份与恢复

    一条命令保存一致的数据库快照与全部登记文件；恢复到新目录，从不覆盖原项目。

    • 留在本地一份 SQLite 和一个文件池，都在你的 Mac 上。
    • 只追加来源快照、版本和决策只增不改，同一请求重放不制造新版本。
    • 如实状态已拉取不等于已处理，已调度不等于已验证。
    • 只读查看页面没有编辑按钮，所有修改都经过 Agent。

    安装

    不用自己装，
    交给你的 Agent。

    把一行提示词发给 Codex。Agent 会下载官方发行版、核对校验值、安装 Yu+ 与两份 Skill、检查飞书，打开你的本地工作空间——然后询问第一个项目的名称。

    Agent 会做什么

    1. 从官方 GitHub Release 下载并校验 SHA‑256。
    2. 升级前先备份已有数据，沿用原数据目录。
    3. 运行统一安装入口，安装两份 Codex Skill。
    4. 检查飞书 CLI 认证，缺失时明确告知。
    5. 启动服务，在 Codex 中打开实际本地地址。
    6. 询问你的项目名称，不导入演示材料。
